Detect duplicate/near-duplicate images across the full dataset (original AND warped) and compute image quality scores (BRISQUE) for all images. This provides the dataset quality audit data needed for the forensics report.

Purpose: Identify data leakage (cross-split duplicates), potential label errors (cross-class duplicates), and low-quality samples that may cause classification failures. The dual-stage approach (original + warped) reveals both inherent dataset issues and warping-induced similarity changes.

Output: Duplicate detection modules, quality assessment module, CSV reports of duplicate pairs and quality scores, distribution visualizations.
</objective>

**src_v2/utils/duplicates.py** - Dual-stage duplicate detection:

1. `detect_duplicates(image_dir, hash_threshold=3, min_similarity_cnn=0.98)` -> Dict
   - Stage 1: Use imagededup PHash to find candidate pairs fast (Hamming distance <= hash_threshold)
   - Stage 2: For candidate pairs from PHash, compute CNN similarity using imagededup CNN method to verify
   - Use conservative thresholds per research: hash_threshold=3, cnn_threshold=0.98 (medical X-rays have high baseline similarity)
   - Process images in batches to avoid loading all into memory at once
   - Return dict: {"pairs": [(img1, img2, hash_dist, cnn_similarity), ...], "total_images": N, "total_pairs": N}
   - Handle errors gracefully (corrupted images, missing files) with logging

2. `classify_duplicate_types(pairs, dataset_structure)` -> Dict
   - Takes duplicate pairs and dataset directory structure
   - dataset_structure maps image filename -> {"split": "train"|"val"|"test", "class": "COVID"|"Normal"|"Viral_Pneumonia"}
   - Classify each pair:
     - "cross_split": images in different splits (CRITICAL - data leakage)
     - "cross_class": images in different classes (CRITICAL - potential label error)
     - "within_split_within_class": same split, same class (less critical - redundancy)
     - "cross_split_cross_class": different split AND different class (MOST CRITICAL)
   - Return dict grouped by type with counts and pair details

3. `compare_original_vs_warped(original_pairs, warped_pairs)` -> Dict
   - Cross-reference duplicate pairs between original and warped datasets
   - Identify "diverged": duplicate in original but NOT in warped (warping differentiated them - good)
   - Identify "converged": NOT duplicate in original but IS duplicate in warped (warping made them similar - concerning)
   - Identify "persistent": duplicate in both (inherent duplicates)
   - Return dict with diverged, converged, persistent sets and counts

**src_v2/evaluation/quality_assessment.py** - Image quality scoring:

1. `compute_quality_scores(image_dir, output_csv=None, recursive=True)` -> DataFrame
   - Use pybrisque BRISQUE to compute quality scores for all images
   - Process with tqdm progress bar
   - Handle grayscale images (convert to RGB for BRISQUE which expects 3-channel)
   - Extract metadata from directory structure: class name from parent dir, split from grandparent
   - Return DataFrame: filename, class, split (if available), brisque_score, path
   - Save to CSV if output_csv provided
   - Handle exceptions per-image (log warning, continue) - don't let one bad image stop the pipeline

2. `analyze_quality_distribution(scores_df, error_sample_indices=None)` -> Dict
   - Compute per-class statistics: mean, std, median, P10, P90 of BRISQUE scores
   - Compute overall statistics
   - If error_sample_indices provided, compare quality of errors vs correct predictions (t-test)
   - Identify outliers: images with BRISQUE > P90 (worst 10%)
   - Return dict with stats, outlier list, and optional error-vs-correct comparison

Follow existing codebase conventions: PEP 8, 100-char line limit, type hints, Google-style docstrings. Import structure: stdlib -> third-party -> local.
